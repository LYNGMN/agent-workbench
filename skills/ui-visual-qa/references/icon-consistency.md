# 아이콘의 통일감·일관성

아이콘을 새로 고르고 SVG로 넣는 일은 `icon-svg-implementation`이 맡는다. 여기에는 **다른 아이콘들과 어울리는지** 검수하는 기준만 적는다.

## 기준
- **한 벌**
  - 한 아이콘 세트만 쓴다(예: Lucide 모양, 선 굵기 1.75).
  - 예외는 기록된 것만 허용한다. 예: 사용자가 정한 Chrome 읽기 아이콘, 브랜드·플랫폼 로고. 예외 요소에는 `data-icon-allow`를 붙인다.
  - 이모지와 글자 기호(×, ✕, ▾, ☰, ⋯ 문자)를 아이콘 대신 쓰지 않는다.
- **같은 스타일**
  - 선형과 채움을 섞지 않는다. 채움은 '선택됨·켜짐' 같은 상태 표시에만 쓰고, 그 요소에 `aria-pressed`, `aria-selected`, `aria-current` 중 하나가 있어야 한다.
  - 선 굵기(stroke-width), 끝 모양(round cap·join), 모서리 둥글기, viewBox(24×24)를 통일한다.
  - 크기가 작아질 때 선 굵기를 따로 바꾸면 같은 묶음 안에서 굵기가 달라 보인다. 묶음 단위로 맞춘다.
- **같은 크기 체계**
  - 쓰임새별 크기를 정해 지킨다. 실제 값은 프로젝트 기준을 따른다. 예: 카드 정보 줄은 16px 아이콘 / 18px 칸
  - 같은 줄·같은 묶음 안에서 렌더 크기가 같아야 한다. 허용 오차는 0.5px다.
  - 실루엣 때문에 크거나 작아 보이는 아이콘은 아래 '광학 균형'대로 재서 보정한다. 보정값은 주석으로 남긴다.
- **같은 뜻은 같은 아이콘**
  - 앱 전체에서 개념 하나에 아이콘 하나를 쓴다. 예: 닫기 = X, 더보기 = ⋯(가로), 설정 = 톱니, 보관 = 같은 북마크, 복사 = 같은 복사 아이콘
  - 서로 다른 개념에 같은 아이콘을 쓰지 않는다.
  - 접근성 이름과 툴팁도 개념마다 같은 말을 쓴다.
- **같은 색**
  - 아이콘 색은 `currentColor`로 테마 토큰을 따른다.
  - 옆 글자와 색 위계를 맞춘다. 보조 정보의 아이콘은 보조 글자색을 쓴다.
  - 밝음·어두움 모두 3:1 이상이어야 한다([theme-contrast.md](theme-contrast.md)).

## 광학 균형 (10-08)
같은 24px 상자, 같은 선 굵기여도 아이콘마다 **보이는 크기와 자리**가 다르다. 같은 묶음(도구 막대, 탭 줄, 카드 바닥 줄)에서는 상자 말고 잉크를 잰다.

- **잰다**: `scripts/measure-icon-optics.mjs <url> --selector "<묶음 버튼>" --ref <기준 아이콘>`을 실행한다. 페이지 안에서는 `icon-optics.js`의 `iconOptics()`를 쓴다.
  - 각 SVG를 실제 화면 변환(CSS transform 포함)과 선 굵기 그대로 캔버스에 다시 그려 잰다.
  - `size`(보이는 크기): 잉크 외곽선(볼록 껍질) 면적의 제곱근을 기준 아이콘과 비교한 값. 잉크 양(점·채움)은 넣지 않는다. 나란히 놓고 보니 점이 많은 팔레트도 외곽선이 같으면 같은 크기로 보였다.
  - `oxPx`·`oyPx`(눈에 보이는 중심): 잉크 상자 중심과 잉크 무게중심의 가운데. T는 윗줄 때문에 무게중심이 위에 있지만, 눈은 외곽선으로 자리를 잡는다. 그래서 둘의 가운데를 쓴다.
- viewBox가 달라도 화면 기준으로 비교한다. `hull`·`ink`·`inkW`·`inkH`는 화면 px(면적은 px²)이라 24·26.667·60 같은 viewBox가 섞인 묶음(Lucide + 브랜드 표시)도 같은 잣대로 잰다.
- **기준**
  - 크기는 기준 아이콘의 ±5%다.
  - X·↗처럼 대각선 획만 있는 아이콘은 외곽선보다 크게 느껴져서 0.93을 목표로 한다. 측정 도구에서는 `--diagonal close`로 표시한다.
  - 눈에 보이는 중심은 아이콘 자리 중심에서 0.5px 이내다.
- **고친다**: 그 묶음 안에서만 path에 `transform`(scale·translate, `transform-box: view-box; transform-origin: center`)을 준다.
  - 선 굵기는 `원래 굵기 ÷ scale`로 되돌려 같은 굵기로 보이게 한다.
  - 아이콘 원본 경로와 다른 화면의 같은 아이콘은 바꾸지 않는다.
  - 값 옆 주석에 보정 전과 후의 측정값을 적는다.
- **눈으로 확인한다**: 숫자만 맞추지 않는다. 4~8배 확대 캡처로 '보정 전 / 숫자 그대로 / 보정 폭 줄인 안'을 나란히 보고 고른다.
  - 10-08에 숫자만 맞춘 안은 X가 크고 팔레트가 작아 보였다. 그 경험으로 기준을 외곽선 면적으로 바꿨다.
- **예시**: 읽기 도구 막대(Lucide, 선 1.7, 기준 = 찾기 search)

| 아이콘 | 보정 전 크기·중심 | 보정 | 보정 후 |
|---|---|---|---|
| x 닫기 | 0.81 | scale 1.18 | 0.93 (대각선 목표) |
| list 목차 | 0.97, 오른쪽 0.8px | translateX −.95, scale 1.04 | 1.01, 0.06px |
| type 글자 | 0.92, 위 1.0px | translateY 1.3, scale 1.06 | 0.96, 0px |
| palette 테마 | 1.11 | translate(.16, .3), scale .9 | 1.01 |
| headphones 듣기 | 1.10, 아래 0.4px | translateY −.42, scale .92 | 1.02, 0px |

## 스크립트가 보는 것 (`check: "icon"`)
- 같은 묶음(조작 요소의 부모)에서 렌더 크기·stroke-width·viewBox·채움/선형이 섞임 → fail
- 세트에서 벗어난 SVG → warn. `--icon-class`를 주면 그 클래스가 없는 SVG를, 주지 않으면 페이지에서 가장 많이 쓰는 선 굵기·viewBox와 다른 SVG를 잡는다. 예외에는 `data-icon-allow`를 붙인다.
- 버튼 안의 이모지·글자 기호 아이콘 → fail
- 같은 접근성 이름인데 SVG 모양이 다름(같은 뜻에 다른 아이콘) → fail
- 같은 모양인데 이름이 다름(다른 뜻에 같은 아이콘일 수 있음) → warn

## 사람이 볼 것
- 스크린샷을 확대해서 굵기·광학 크기·모서리가 한 벌처럼 보이는지 본다.
- 새 아이콘을 넣었다면 앱의 같은 개념에 이미 쓰는 아이콘이 있는지 코드에서 검색한다(예: `grep -rn "lucide-react" | grep X`).
