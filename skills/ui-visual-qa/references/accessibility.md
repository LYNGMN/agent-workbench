# 시각·청각 접근성 (WCAG 2.2 AA)

기준은 `wcag22-vibe-coding` 스킬이 소유한다. 성공 기준의 전체 목록과 준수 판단은 그 스킬의 references를 읽는다. 여기에는 UI 검수 때 자주 걸리는 항목만 적는다.

**보고 형식**: 기준 번호와 수준, 사용자에게 주는 영향, 고친 내용, 확인 방법(자동/수동)을 적는다. 자동 도구로는 준수를 증명할 수 없다. "WCAG 준수"라고 단정하지 않는다.

## 시각 (저시력·전맹·색각)
| 확인 | 기준 | 자동 |
|---|---|---|
| 아이콘만 있는 버튼에 현재 UI 언어의 접근성 이름(한국어 UI에서만 한국어, 다국어 문구 표로 번역). 툴팁과 같은 문구 | 4.1.2, 2.5.3, 3.1.2 | ✓(있는지만) |
| `<html lang>` | 3.1.1 | ✓ |
| 의미 있는 HTML(button, a, nav, main, 제목 순서). ARIA보다 원래 HTML 먼저 | 1.3.1 | 일부 |
| 키보드만으로 모든 기능, 키보드 함정 없음, 논리적 초점 순서 | 2.1.1, 2.1.2, 2.4.3 | 일부(Tab 60번) |
| 초점이 보임, 고정 머리줄·하단 막대에 가려지지 않음 | 2.4.7, 2.4.11 | ✓ 러너 |
| 대비: 글자 4.5:1, 아이콘·경계 3:1 | 1.4.3, 1.4.11 | ✓ |
| 색으로만 구분하지 않기(선택·오류에 아이콘이나 글자를 함께) | 1.4.1 | 수동 |
| 200% 확대, 320px 리플로, 글자 간격을 늘려도 잘림 없음 | 1.4.4, 1.4.10, 1.4.12 | 일부 |
| 화면 방향 고정 금지 | 1.3.4 | 수동 |
| 저장·복사·오류 같은 결과를 `aria-live`/`role=status`로 알림 | 4.1.3 | ✓(있는지만) |
| 이미지 대체 텍스트, 장식 이미지는 `alt=""` | 1.1.1 | ✓ |
| 조작 영역 24px 이상(프로젝트 기준 44px) | 2.5.8 | ✓ |
| 줄임 동작 설정 존중, 깜빡임 없음 | 2.3.3(권장), 2.3.1 | 일부 |

## 청각 (농·난청)
| 확인 | 기준 |
|---|---|
| 녹화 영상에 자막. 서비스의 자막·대본 기능과 연결한다 | 1.2.2 |
| 영상 내용을 글로 읽을 수 있는 대본 | 1.2.1, 1.2.3 |
| 3초 넘게 자동 재생되는 소리는 멈추거나 줄일 수 있음 | 1.4.2 |
| 소리로만 알리는 신호를 쓰지 않고 화면 표시를 함께(필요하면 진동도) | 1.3.3 취지 |
| 자막 켜기/끄기, 자막 글자 크기 조절 | 사용성 |

`<video>`·`<audio>`에는 `<track kind="captions|subtitles">`가 있는지 자동으로 본다. YouTube 같은 iframe 플레이어는 자막 제공 여부를 수동으로 확인한다.

## 수동 확인 (한 번은 꼭)
- macOS VoiceOver(⌘F5)로 바꾼 화면의 주요 흐름을 읽어 본다. 버튼 이름, 상태 알림, 메뉴가 열리고 닫힌 뒤 초점이 어디로 가는지 확인한다.
- 휴대폰 VoiceOver·TalkBack 확인은 실기기가 필요하다. 필요하면 사용자에게 요청한다.
