# 다른 Pine 인디케이터에 사용하는 복사 프롬프트

아래 대괄호만 대상에 맞게 바꿔 사용한다.

```text
대상 Pine Script v6 파일: [절대 경로]
검증 스크립트: [있으면 절대 경로]

이 인디케이터의 텍스트·말풍선·아이콘·수치 신호 배치를 품질 높게 개선해 주세요. 신호 판정식은 바꾸지 말고, 신호가 기준 캔들·피벗·볼린저밴드·이평선·VWAP 등 의미 기준에서 과도하게 멀어지지 않으면서 캔들 wick 및 같은 봉의 다른 신호와 겹치지 않게 해야 합니다.

필수 계약:

1. 먼저 모든 신호를 instanceKey, 조건, 방향, 발생 봉, 기준 가격, 스타일, 크기, 줄 수, 안쪽/바깥쪽 extent, 수평 폭 등급, 우선순위로 인벤토리화합니다. 같은 ID가 한 봉에 여러 번 생길 가능성도 확인합니다.
2. 신호를 즉시 그리지 말고 상단/하단 활성 큐로 수집합니다. 활성 신호만 고정 순서로 연속 배치하며 사용자가 켠 신호를 모두 각각 표시합니다.
3. `+N`, 통합 배지, tooltip-only, 조용한 생략은 제가 명시적으로 허용하지 않는 한 사용하지 않습니다.
4. 첫 앵커는 wick 바깥의 작은 적응 간격에서 시작합니다. 현재 봉 범위로 첫 간격의 상한을 두고, 후속 간격에는 ATR 하한과 최소 2틱 fallback을 둡니다. 캔들 세기는 3봉 정도 평활하고 좁은 배수 범위에서 간격만 바꿉니다.
5. 소스의 활성 조건을 만족하고 값이 `na`가 아닌 선 중 첫 앵커 가까이에 있는 선만 회피합니다. 먼 선 때문에 전체 스택이 캔들에서 멀어지면 안 됩니다. Pine은 모습 탭에서 사용자가 plot을 수동으로 숨긴 상태를 읽지 못한다는 한계를 명시합니다.
6. 후속 신호는 실제 말풍선/텍스트 여부, 크기, 줄 수로 계산한 extent proxy를 사용합니다. 방향형 라벨의 안쪽 포인터 영역과 바깥 본체 영역을 나눠 `이전 outer + 현재 inner + 최소 여백`만큼 바깥쪽으로 쌓습니다. 긴 한 줄 문구의 수평 폭은 별도 width class로 관리합니다.
7. 위쪽 신호는 `label.style_label_down`, 아래쪽은 `label.style_label_up`을 사용합니다. 배경 없는 숫자·텍스트·아이콘도 `label.style_none`이나 center 스타일을 쓰지 말고 투명 배경의 방향형 라벨로 렌더링합니다.
8. 다이버전스는 원래 피벗/확정 봉의 X를 유지합니다. 같은 봉과 바로 이웃 봉의 등록된 스택 꼬리를 확인해 Y만 바깥으로 조정하고, 빈 곳을 찾을 때까지 X를 이동하지 않습니다. 과거 스택 reflow가 없다면 늦게 확정된 다이버전스는 등록된 tail 바깥에 둡니다.
9. `xloc.bar_index`, `yloc.price`, 기존 overlay와 가격축을 유지해 캔들·선·신호가 확대축소와 가격축 이동에서 함께 움직이게 합니다.
10. 기존 `alertcondition()`과 모든 동적 `alert()`의 조건, 제목, 메시지, `freq`, 실행 게이트, 호출 위치·횟수·대표 발생 trace를 보존합니다. 실제 소스에 있는 모든 `plot*`, `fill`, `hline`, `bgcolor`, `barcolor`의 비대상 선언과 스타일을 스냅샷하고 설정 → 모습 탭의 기존 색·불투명도·선 스타일·두께 편집성을 유지합니다.
11. 변경 전후 plot count는 동일하고 64 이하이며 여유를 남겨야 합니다. 각 선언의 count 소비 여부는 Pine 규칙과 서버 컴파일로 구분합니다. label/line 객체 한도와 IL token도 관리하고 TradingView 서버 컴파일 성공을 token 완료 증거로 사용합니다.
12. Pine은 viewport 픽셀과 라벨 bounding box를 읽지 못하므로 “모든 줌에서 픽셀 절대 무충돌”을 허위로 보장하지 마세요. 대신 같은 봉의 논리적 무충돌, wick 반대 방향 렌더링, 제한된 이웃 회피를 자동 검증하고 Auto/확대/축소/가격축 이동의 대표 화면을 실제 확인합니다.

구현 전 실패 테스트를 추가하고, 변경은 작은 체크포인트로 나누세요. 완료 보고에는 plot count, 알림/스타일 보존, 로컬 검증, TradingView 서버 컴파일, 실제 화면 검증, 남은 Pine 한계를 각각 분리해 적으세요. 기존 저장 스크립트 덮어쓰기, 공개, Push, PR은 별도 승인 없이는 하지 마세요.
```

신호가 아주 많은 지표에서는 프롬프트 끝에 다음을 추가한다.

```text
한 봉에서 동시에 가능한 최대 신호 수와 모든 라벨의 최악 점유 높이를 먼저 계산하세요. “모두 표시”와 “[허용 최대 거리] 이내”가 동시에 불가능하면 임의로 숨기지 말고, 약어·크기·최대 동시 표시·보존 구간 가운데 어떤 계약을 조정해야 하는지 근거와 함께 보고하세요.
```
