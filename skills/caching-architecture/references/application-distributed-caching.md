# 애플리케이션·분산 캐싱

## 데이터 분류표

캐시 후보마다 다음을 채운다.

| 항목 | 질문 |
|---|---|
| 변경 빈도 | 누가, 얼마나 자주 쓰는가? |
| 공유 범위 | 요청, 사용자, 테넌트, 모든 사용자 중 어디까지 같은가? |
| 크기 | 단일 값과 컬렉션은 어디까지 커질 수 있는가? |
| 민감도 | 개인정보·권한·비밀이 포함되는가? |
| freshness 예산 | 오래된 값이 최대 얼마 동안 허용되는가? |
| miss 비용 | 원본 조회의 지연·QPS·금전 비용은 얼마인가? |

설명과 가격처럼 수명주기가 다르면 객체 전체를 한 키·TTL로 묶지 않는다.

## 로컬과 분산 캐시

| 선택 | 적합한 경우 | 비용 |
|---|---|---|
| 로컬 캐시 | 거의 안 변하는 작은 데이터, 인스턴스별 차이가 허용됨 | 가장 빠르지만 인스턴스 수만큼 복제되고 무효화·동기화가 어렵다 |
| 분산 캐시 | 여러 인스턴스가 같은 동적 상태를 공유해야 함 | 네트워크 왕복, 별도 장애·메모리·운영 비용이 생긴다 |
| 다단 캐시 | 매우 뜨거운 읽기가 분산 캐시도 압박함 | L1/L2 간 stale 창과 이중 무효화를 명시해야 한다 |

인스턴스가 많다는 이유만으로 로컬 캐시를 금지하지 말고, 일관성 비용을 이득과 비교한다.

## 읽기·쓰기 패턴

- **cache-aside**: 애플리케이션이 miss 시 원본을 읽고 저장한다. 단순하지만 stampede와 쓰기 무효화를 직접 책임진다.
- **read-through**: 캐시 계층이 원본 로딩을 숨긴다. 공급자 기능과 오류 동작을 확인한다.
- **write-through**: 캐시와 원본을 동기 경로에서 갱신한다. 일관성은 단순해지나 쓰기 지연·부분 실패가 늘어난다.
- **write-behind**: 캐시 쓰기 후 원본을 비동기 갱신한다. 데이터 유실·순서 역전이 허용되고 복구 로그가 있을 때만 쓴다.
- **refresh-ahead**: 만료 전에 인기 키를 갱신한다. 예측 가능한 hot set에서만 효율적이다.
- **negative cache**: 존재하지 않음도 짧게 저장한다. 새 데이터 생성 지연과 공격성 key space를 함께 고려한다.

## 키·TTL·무효화

- 키에는 스키마 버전, 테넌트, 리소스 ID, 언어, 권한 등 **응답을 바꾸는 차원**만 넣는다.
- 원문 이메일·토큰 같은 민감값 대신 내부 ID나 안전한 파생값을 사용한다.
- TTL은 `허용 stale 시간 - 감지/전파/갱신에 필요한 최악 시간` 안에서 정한다. 근거가 없으면 숫자를 확정하지 말고 부하 시험용 시작 범위라고 표시한다.
- jitter는 만료 집중을 흩뜨리는 범위이지 보편적인 고정 백분율이 아니다. freshness 예산 안에서 측정해 정한다.
- 쓰기의 최종 성공을 누가 판단하고, 성공 전후 언제 어떤 키를 무효화하며, 실패 시 누가 재시도하는지 적는다.
- 순서 보장이 어렵다면 버전 키나 이벤트 버전을 사용해 오래된 갱신이 새 값을 덮지 못하게 한다.

## 서로 다른 실패 유형

| 문제 | 증거 | 대표 완화 |
|---|---|---|
| stampede | 한 인기 키 만료 직후 원본 동시 조회 | single-flight/request coalescing, 제한된 lock, refresh-ahead, jitter |
| penetration | 존재하지 않는 키가 계속 원본 통과 | 입력 검증, negative cache, 필요 시 Bloom filter |
| avalanche | 많은 키가 같은 시각 만료·노드 장애 | 만료 분산, 용량 여유, 장애 도메인 분산 |
| pollution | 다시 읽지 않을 값이 hot set을 밀어냄 | admission 기준, TTL·크기 제한, 캐시 제외 |

## 장애와 검증

- 캐시 호출에 짧고 측정된 timeout을 두고 circuit breaker와 동시성 제한을 둔다.
- fallback은 원본이 감당할 수 있는 QPS까지만 허용한다. 필요하면 stale-if-safe, rate limit, degraded response를 사용한다.
- 변경 전후 hit ratio, p50/p95/p99, 원본 QPS/CPU, cache timeout/error, eviction, stale 비율, 메모리 사용량을 같은 부하에서 비교한다.
- cold start, 캐시 전체 장애, 한 hot key 만료, 쓰기 직후 읽기, 배포·롤백을 시험한다.
